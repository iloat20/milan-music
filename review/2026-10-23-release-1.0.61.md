# 米兰音乐 1.0.61

本版是 1.0.53 之后第一次入库，累积了 1.0.54~1.0.61 共 8 个批次。功能层面集中在两处：
播放页的状态归属，以及封面像素的曲目作废语义。

## 播放页不再依赖 DI 容器

`PlayerScreen` 原先直接接收 `AppContainer`，由此带来三个后果：收藏有两条写路径
（播放页直连 `userData`，列表页走 ViewModel）、`userData` 被订阅两次、播放页无法脱离
真实容器做任何测试。

本版新增 `PlayerViewModel`，播放页的签名变为
`PlayerScreen(PlayerViewModel, PlayerController, ArtworkRepository, onBack)`：

- `playback` / `progress` 纯转发，不套 `stateIn`（否则 `PlayerController` 的 ticker
  过滤条件会被永久打开）
- 收藏收敛为 `viewModel.toggleFavorite` 一条写路径
- `userData` 只订阅一次

`PlayerController` 与 `ArtworkRepository` 仍然从外面传进来，只喂给封面轮播：轮播需要
等会话确认换曲（`player.state.first { … }`）才肯翻页，把控制器抄进 ViewModel 会让同一份
状态在两处各自演化。

## 封面像素按曲目作废

原实现里 `edgeHaze` / `heroCover` / `reflection` 三个变量只在加载成功时写入，换曲不清空。
遇到没有内嵌封面的曲目，`bandCover = syncCover ?: heroCover` 会把**上一首封面的镜像**铺进
倒影带——内容错了，不是占位。

本版新增 `PlayerArtwork`，按 `trackId` 归属，`forTrack(id)` 是唯一判据。换曲后到解码完成
之间的 1~3 帧里手上没有可用产物：

- 上缘糊版退回色场（原先是继续画上一首的糊版）
- 倒影带子退回同步缓存（隔壁页早已解码，基本都命中）
- 无封面曲目 `bandAvailable = false`，走已文档化的降级：封面底边淡出、不画带子

宁可这几帧没有，也不要把上一首的图停在别人的位置上。

## 一并入库的倒影带子工作（1.0.54~1.0.59）

- **模糊半径阶梯 + 单位分解权重**：`w_i = rise_i − rise_{i+1}`，任意高度上权重和恒为 1。
  取代此前"清晰版与糊版按透明度交叉淡入"的做法——那在物理上是重影，中段同时看得见
  清晰的边和它的糊影（真机实测该段 RMS 10.0，比清晰封面本身还高）
- **逐行像素映射**：倒影按 `coverRowAt` 显式取样并翻转，不再靠 `Image(contentScale,
  alignment)` 定位。旧画法的正确性依赖"缩放后高度 == 框高"，而倒影节点高度不等于封面
  框高，走 `widthRatio` 分支就会整体滑动，过渡带里出现封面中段（表现为"封面出现了两次"）
- **叠层随封面横移**、**带子与翻页同帧**：切歌不再闪一下
- **1.0.55 修叠层报高**：挂在 `Column` 里的"只绘制"节点必须报 0 高，否则整页被撑爆、
  控件全部出界
