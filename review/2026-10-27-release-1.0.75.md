# Release 1.0.75 (vc 76, b76)

本批是 P1-b：**桌面小组件在进程冷启动后不再显示空卡片**。包里同时包含上一批
（1.0.74 / b75）的会话断连兜底与权限撤销回退——那一版打过包但未发布，内容原样并入本包，
版本号让过 1.0.74 以免与设备上可能已安装的包混淆。

基线：AGP 9.4.1 / Kotlin 2.4.21 / Gradle 9.8.2 / compileSdk 37 / minSdk 26。

## 问题

`MusicWidgetProvider.render()` 只读 `container.player.state.value`。而
`MilanMusicApp` **刻意不在这里 connect**（连接由曲库页负责，见该文件注释），所以：

- 开机、launcher 重启、进程被低内存杀掉之后，系统调用 `onUpdate` 时进程是新的，
  controller 没绑定、`state` 为空 → 组件画成 `app_name` + 播放三角；
- 此时快照（`PlaybackSnapshotStore`，就是为这个场景存的）里明明有 `current: SnapshotTrack`
  和 `wasPlaying`，却没有任何人读它。

用户看到的是"听歌记录被清空了"，直到手动打开一次应用才恢复。

## 改法

- `render()` 在 `live.currentTrack == null` 时读一次 `playbackSnapshot.load()`，
  用它兜底曲目与播放态；有 live 曲目时**不读**（DataStore 是文件读，而且 live 永远更新）。
- 判定收进纯函数 `resolveWidgetDisplay(...)`（`widget/WidgetDisplay.kt`）：
  live 优先 → 快照次之 → 都没有才是 app 名。播放图标跟随**来源**：暂停状态的快照恢复出来
  就是暂停的会话，卡片必须画播放三角，不能画暂停条。
- 播放键的 `PendingIntent` **仍然只看 live 队列**（`widgetPlayAction(live.hasQueue)`）。
  快照不是一个已绑定的会话：在进程里没有 controller 的情况下发 TOGGLE，只会绑上一个空队列
  然后什么都不做。冷启动的点击继续走 "打开 Activity + `EXTRA_PLAY_ON_START`"，与
  Android 17 后台音频收紧后的既有规则一致（`WidgetPlayPolicyTest` 仍然守这条）。
- 快照读取用 `runCatching` 兜住并以 warn 记账：组件渲染失败会让整个 launcher 更新被跳过，
  降级成"显示应用名"远好于一张空卡片。
