# Release 1.0.79 (vc 80, b80)

本包汇总 `v1.0.69` 之后**十版积压**（1.0.70 ~ 1.0.79），一次装机即可升到这里。
只有 1.0.79 那一版动了视觉（倒影层数、进度条命中区）；其余九版是正确性与健壮性修复，
界面行为应与你熟悉的 1.0.69 一致。

基线：AGP 9.4.1 / Kotlin 2.4.21 / Gradle 9.8.2 / compileSdk 37 / minSdk 26。
ABI 只有 `arm64-v8a`。

## 值得单独说的六条

### 一 · 点播放键会崩（1.0.74）

三处条件叠加才会崩：`PlayerController` 从未给 `MediaController.Builder` 设
`setListener` → 会话断开后 media3 把 controller 置为 released 而字段仍指向它 → 此后任何
`play()` / `pause()` / `seekTo()` 都走 `checkNotReleased()` 抛
`IllegalStateException`，而 `AppContainer.scope` 没有 `CoroutineExceptionHandler`，
异常直达 `Thread.uncaughtExceptionHandler`。低内存杀 service、系统后台限制、在设置页
"停止"应用后回前台点播放，都能触发。现在 `onDisconnected` 主动 `detachSession()`，
所有会话调用过一层只捕 `IllegalStateException` 的 `sessionCall {}`。

### 二 · 小组件冷启动是空卡片（1.0.75）

`MusicWidgetProvider.render()` 只读 controller 的 `state`，而 `MilanMusicApp` 刻意不在
这里连接 —— 开机 / launcher 重启 / 进程被杀之后 `state` 为空，组件画成应用名 + 播放三角，
而 `PlaybackSnapshotStore` 里明明存着上次那首歌。现在 `currentTrack == null` 时读一次快照
兜底，读取失败按无数据处理。

### 三 · 快速轻扫不翻页（1.0.76）

纵向收起与封面横滑原来每个指针事件都 `scope.launch { offset.snapTo(…) }`，而
`rememberCoroutineScope()` 用的是 Handler 调度器 —— 同一批指针事件里 `onDrag` 与
`onDragEnd` 连着跑，`onDragEnd` 读到的是上一批的位移，于是**甩一下不动、慢慢拖才翻得动**。
改成 `ui/util/DragOffset.kt` 的同一点写入（同步赋值 + 自带取消的 `animateTo`）。
同一版还给播放快照的两路并发写加了 `Mutex`，并新增 `position_index` 让位置能否套到当前
队列有精确判据 —— 否则冷启动会从新歌的第 N 秒开始播。

### 四 · "移除动画"开了还在动（1.0.77 + 1.0.73）

Compose 只把**有限**动画的时长乘 `ANIMATOR_DURATION_SCALE`；`rememberInfiniteTransition`
没有终点，永远不会停。列表里那三根"正在播放"的柱因此在开发选项里关掉动画后仍在呼吸。
1.0.73 让它早返回静态柱，1.0.77 补上运行期监听：系统设置一变，`ContentObserver` 通知，
界面当场静止，不必等重启。

同一版把播放时间标签改成 `String.format(Locale.ROOT, …)` —— `ar` / `fa` / `bn` 下标签会用
本地数字，秒数一跳宽度就变，进度条两端逐秒左右微移。

### 五 · 倒影阶梯 5 层 → 3 层（1.0.79）

`BlurRamp` 6 个 stop 收到 4 个，去掉 `2dp @ -86dp` 与 `22dp @ 96dp`。它们几乎落在邻两级
连线上（整条曲线偏差 ≤1.2dp），而镜面线的 12dp 与 `CoverRamp` 的 128dp 原样保留，
所以**接缝锚点没动**。1080×2400 上省掉约 20MB GPU 缓冲。

离线复刻（`review/ramp3-compare.py`）用真机截图跑出的接缝两侧逐像素差：

```
接缝 ±8dp        平均 0.00/255   最大 0/255   <- 逐像素完全相同
镜下 0..64dp     平均 3.09/255   最大 12/255
镜下 64..128dp   平均 7.87/255   最大 17/255
```

接缝完全一致是结构性的：镜面线两侧由同一层、同一次模糊、同一张位图的相邻两行画出。
唯一变糊的是 64..128dp 那段（`fadeAt` 已衰减到 50% 以下），放大 2 倍并排看无差别、
也没有带状边界。若真机上读成"糊成一团"而非"化进色场"，旋钮是最后一档半径 34dp → 28dp。

### 六 · 进度条命中区 26dp → 48dp（1.0.79）

外面 `Box(48dp)` 承担手势与语义，里面的 `Canvas(26dp)` 原样贴底，`ProgressTopGap`
从 26dp 收到 4dp —— **只向上扩**（26 + 26 = 52 = 4 + 48），条的中心、时间标签、播放控制
的绝对位置一格没动，多出来的只是原来空着的可点区域。

顺带修掉同一段里另一个缺陷：两个 `pointerInput(durationMs)` 拿**时长**当 key，时长一变
（首帧 0 → 会话报出真实值、或切歌）就把正在进行的拖动取消，手指还在屏幕上条却弹回去。
改成 `pointerInput(Unit)` + `rememberUpdatedState`。

## 待真机验证

以下十条在 JVM 里都观测不到（执行器调度、主线程唤醒频率、TalkBack 语义树、GPU 缓冲），
所以没有为它们造门禁，只能上手看：

1. 断开连接后点播放键不崩（低内存杀 service 后回前台，或设置里"停止"应用）。
2. 撤销音频权限后界面退回权限门，重新授权后能自己回到曲库。
3. 小组件：开机 / launcher 重启后应显示上次那首歌，不是应用名 + 三角。
4. 封面横滑：快速轻扫也要能翻页（旧版只有慢慢拖才翻得动）。
5. 倒影接缝：整幅封面可见 / 横滑移开一半 / 切歌瞬间，三个位置都不该有亮线、暗线或
   清晰度跳变。
6. 进度条形变：在条上方约 20dp 处横划也能拖；点一下能跳转；按住拖动时自然切歌，
   手指底下的条不应弹回。
7. 开发选项里关掉动画：列表里"正在播放"的三根柱应当场静止，不必重启。
8. 切到 `ar` / `fa` / `bn` 语言：进度条两端时间标签不应逐秒左右微移。
9. 无专辑标签的曲目（`albumId=0`）不再挤成一个巨块，应按专辑/艺人文本分组。
10. 深色主题下迷你播放器与排序面板出现时各扫一次高光；浅色主题不扫（实测浅色只亮 2 级、
    文字被洗 5.1 级，收益为零）。
