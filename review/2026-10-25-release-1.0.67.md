# Release 1.0.67 (vc 68, b68)

本包汇总 1.0.65 之后未发布的四个批次：播放链路缺陷修复、切曲写放大与音频观测、
ReplayGain 响度归一化、冷启动扫描与首播的 IO 分离。
基线：AGP 9.4.1 / Kotlin 2.4.21 / Gradle 9.8.2 / compileSdk 37 / minSdk 26。

> 版本号从 66 直接到 68：`b67` 的 APK 曾在本地打出但对应代码从未提交，
> 跳过 67 以免与设备上可能已安装的包混淆。

## 播放链路缺陷修复

- **小组件播放键失效**：应用进程死亡后，桌面仍持有渲染当时生成的广播型
  `TOGGLE` PendingIntent；新进程 `queueSize=0` 时旧实现只记日志并返回。
  现在点击时用 `widgetToggleAction()` 重判实时队列，空队列改为发
  `playOnStart=true` 的 Activity PendingIntent，走可见链路起播。
- **带保存状态恢复时丢失显式播放请求**：`MainActivity` 原先只在
  `savedInstanceState == null` 时消费 `EXTRA_PLAY_ON_START`。从小组件冷启动
  恢复任务时该参数通常非空，请求被静默丢弃。改为 `nextPlayRequest()` 单纯由
  Intent 决定，恢复态同样消费且只消费一次。
- **启动中退后台导致播放任务被永久取消**：`autoStarted` 在队列真正安装前就置位，
  控制器仍在绑定期间 `onUiStopped()` 会因空队列 `release()`，清掉待执行的
  `playQueue`。新增 `shouldReleaseOnUiStopped()`：只要还有未执行的命令就不释放。
- **换曲启动延迟被污染**：暂停快照仍会 `prepare()` 并触发转场打点，用户 N 秒后
  才点播放，这 N 秒被计入"换曲 → 出声"。改为 `TrackStartProbe` 状态机，
  以播放请求或真实缓冲为起点；无缝转场单独记 `0ms`，等待不计入。

## 性能

- **切曲不再重写整个队列快照**：`onMediaItemTransition` 原先每次都把整条队列
  重新序列化（1 233 首约 12 KB）并触发两次 DataStore 原子重写，而队列结构没变。
  新增 `QueueSnapshotPolicy` 按事件语义判定写范围，`PlaybackSnapshotStore.saveCursor`
  只写索引/当前曲/位置；`persistCursor` 执行时重读索引，排队中的全量写入不会被
  旧游标覆盖。
- **音频链路可观测**：`diag/AudioPipeline` 接入现有 `AnalyticsListener`，
  输出 `audio underrun buffer= bufferMs= sinceFeedMs=` 与
  `audio input rate= ch= pcm=`。`pcm=float` 是 float 输出真正生效的唯一证据，
  `bufferMs` 才能区分解码抖动与存储停顿。
- **冷启动扫描与首播 IO 分离**：扫描改到专用单线程（`library-scan`），不再占用
  共享 `Dispatchers.IO`；缓存已上屏时视为后台对账，降到
  `THREAD_PRIORITY_BACKGROUND` 并等首帧出声后再开始（上限 1 500 ms）。
  无缓存时保持默认优先级且不等待——此时扫描就是首屏。

## 音质

- **ReplayGain 响度归一化（固定启用）**：`player.volume = clamp(10^(gain/20), 0.05, 1.0)`。
  只衰减不提升，因此不需要自定义 `AudioProcessor`、不需要 limiter，也不与 offload 互斥。
- 支持 FLAC（`VORBIS_COMMENT`）、Ogg Vorbis / Opus（按内容标记识别）、
  MP3（ID3v2.3/2.4 `TXXX`，v2.4 按 syncsafe 解析）；`TRACK_GAIN` 优先，
  回退 `ALBUM_GAIN`，key 大小写不敏感。
- 不支持 MP4/M4A（`moov` 可能在文件尾）与 ID3v2.2（3 字符 frame id，误读会得到
  错误增益），两者显式返回无标签、按母带电平播放。
- 读取窗口自适应：FLAC/Ogg 读 64 KB；ID3 按自带 `tagSize` 最多扩到 1 MB
  （带内嵌封面的 MP3 其 `TXXX` 常在标签末尾）。
- 音量保持上一曲水平直到标签就绪，不重置为 1.0，避免每次切歌的音量尖峰。

## 顺带修掉的崩溃

- ReplayGain 解析器原先用 `offset + length > end` 判界：`length = Int.MAX_VALUE`
  时和溢出为负、绕过检查，损坏标签会在切歌时直接
  `ArrayIndexOutOfBoundsException` / `StringIndexOutOfBoundsException` 崩进程。
  四处全部改为减法形式（`length > end - offset`）。

## 诊断

- `diag/PlaybackFailure`：把播放错误按 code + cause 分类，`StuckPlayerException`
  被包成 `ERROR_CODE_UNEXPECTED` 时仍能识别；卡死不自动重试（`autoRetryAllowed`）。
- `diag/ExitReasonReporter`（API 30+）：读取应用上次退出原因，IO 线程，
  `SharedPreferences` 去重，同一原因只报一次。
- `diag/MemoryBaseline`：`onTrimMemory` 时采 `Debug.getMemoryInfo`，给出
  `mem pressure= heap= used/max MB pss=`。
- 日志字段是契约：`kind= code=` / `exit cause= reason= atMs= rss= pss= desc=` /
  `track start latency=<ms>ms`。过滤用
  `adb logcat -s PlaybackService ExitReasonReporter MemoryBaseline AudioPipeline`。
