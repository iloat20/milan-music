# Release 1.0.76 (vc 77, b77)

本批是 P2-a，两条独立的正确性缺陷：

1. **手势位移的写入被推到了调度器上** —— 快速轻扫的最后一段行程对阈值判定不可见。
2. **播放快照有两路并发写** —— 位置可能被落成"属于上一首"，冷启动从新歌的第 N 秒开始播。

基线：AGP 9.4.1 / Kotlin 2.4.21 / Gradle 9.8.2 / compileSdk 37 / minSdk 26。

## 一 · 拖动每帧 `scope.launch { snapTo }`

`PlayerScreen`（纵向收起）与 `CoverCarousel`（封面横滑）原来每个指针事件都做一次
`scope.launch { offsetY.snapTo(...) }`。`snapTo` 是 suspend，而 `rememberCoroutineScope()`
用的是组合的调度器（Android 上是一个 Handler）：**同一批指针事件里的 `onDragXxx` 与
`onDragEnd` 是连着跑的**，`onDragEnd` 读到的还是上一批留下的位移。后果是快速轻扫的最后
一段行程完全不计入阈值 —— 甩一下不翻页，慢慢拖反而翻得动。每个移动事件还额外分配一个
协程对象，并靠 `MutatorMutex` 互相取消。

改法：新增 `ui/util/DragOffset.kt`，两块位移共用一个写入点。

- `set(target)` 是**同步**的 `MutableFloatState` 赋值，绘制期读，不触发重组。
- `animateTo(target, spec) { … }` 由它自己起协程，任何一次 `set` 先把动画 cancel 掉 ——
  这正是 `Animatable.snapTo` 靠 MutatorMutex 保证的语义，只是这里只有一条写路径。
- 需要的串行路径（翻页：滑完一个 pitch 再向会话请求切歌）用返回的 `Job.join()`；
  被打断时 `slide.isCancelled` 直接返回，**不再隔着一步去切歌**。
- `isAnimating` 的复位挪进 `finally`：这个块现在有提前返回，漏一次复位所有手势都会失效。

顺带修掉两处只在这个结构下才成立的隐患：

- **预测式返回松手后播放页卡在半途**：`catch (cancellation) { offsetY.animateTo(0f, Sheet) }`
  原先跑在一个**已被取消**的协程里，第一帧就抛 `CancellationException`，回弹从来没发生，
  页面留在预览位置。现在动画落在组合作用域上，真的会弹回去。
- **收起播放页改成 `onFinished` 回调**：动画被打断时不再卸载 overlay。

## 二 · 快照两路并发写

每个写入方都是"读播放器状态 → 写队列 store → 写位置 store"，三条路径（切歌的 CURSOR、
时间轴变化的 FULL、十五秒一次的 ticker）各自 `launch`，落到 `Dispatchers.IO` 上并行执行，
完成顺序与发起顺序无关。两种后果：

- 旧的写入后落地，把新的 index 覆盖回去 → 冷启动回到**上一首**；
- ticker 带着上一首的位置后落地，时间戳更新 → `load()` 的纯时间戳判据采信它 →
  冷启动从新歌的第 37 秒开始播。

改法两道闸：

1. `PlaybackService.snapshotWriteLock`（`Mutex`）：`persistQueue` / `persistPosition` 的
   "读 + 写"整段加锁，最后落地的一定是最后发起的。`persistCursor` 只从锁内调用，不再单独加锁。
2. `PlaybackSnapshotStore` 新增 `position_index`：位置落盘时一起写下"它属于第几项"，
   `load()` 用 `positionMatchesQueue(...)` 判定。这是**精确**判据，进程在两次 edit 之间被杀
   （锁已不存在）时仍然有效；时间戳退化成第二道闸，挡"同一个 index 但队列被换过"（重扫后
   同位置换了歌）。`position_index` 缺失的老快照退回纯时间戳，升级不丢位置。

同时修掉 `PlaybackSnapshot.currentIndex` 的错误注释（写的是"unshuffled"，实际就是
`saveQueue` 保存的 timeline 顺序，shuffle 已经作用过）。

## 待真机验证

- **封面横滑**：快速轻扫（短行程、高速）应能翻页；慢慢拖过 80dp 也应翻页；轻点两次仍翻页。
  翻页过程中**不能**出现"封面停在半路、曲目已经换了"的一帧。
- **下滑收起**：拖过 110dp 松手 → 滑出后回到首页；未过阈值松手 → 弹回（手感应比上一版更贴手，
  因为不再是每帧排一次队）。
- **预测式返回**（Android 14+）：从屏幕边缘右滑到一半松手 → 播放页必须弹回原位，而不是停在半途。
- **冷启动续播**：听一首到 3 分钟以上 → 连点下一首若干次 → 杀进程（不要正常退出）后重开：
  应该回到最后那一首、且位置不是上次那首的秒数（进位串台）。
