# 第 16 批：玻璃体从「暖白薄幕」换成「中性暖灰烟面」

日期：2026-10-22
起因：用户贴出 macOS 27 控制中心的笔记本截图，指出「这种效果才对，现在的实现距离液态玻璃差很远」。
产物：`dist/milan-music-1.0.53-smokebody-20261022.apk`（2,460,184 B，SHA-256 `ad3484af…dd44`）

## 一、先定位差距，而不是继续调边缘

边缘这一层在第 13–15 批已经改了三轮（1dp 白描边 → 上亮下暗渐变 → 外亮内暗双层），
每次都在同一个地方被否。这次先不碰边缘，改去量「体」。

拿参考截图沿胶囊上缘逐行取亮度，得到两条互相对立的事实：

| 位置 | 背景 | 玻璃内部 | 结论 |
|---|---|---|---|
| 压在壁纸暗部（`x=380`，y 300 一带） | lum 12.7 | lum ≈ 40 | **提亮** |
| 压在壁纸亮脊上（`x=430`） | lum 19 → 内部 157 | — | 只是把结构搬进来 |

也就是说：桌面版玻璃不是「把背景加白」，而是**跟着背景走**——暗处被抬起、
亮处被压低，中间调基本不动，同时色相被保留。这是一条斜率和截距都改了的曲线，
一层固定 alpha 的白幕做不到。

而 MilanMusic 当时实装的是：`GlassSurface` 里写死 `Color(0xFFF8F1E2) @ 6%`（深色主题）。
用同一套参数在真实素材上渲染，实测：

| 底图 | 透过亮度比 | Δ饱和度 |
|---|---|---|
| macOS 壁纸（高对比彩色） | **×1.06** | **−0.05** |
| 播放页专辑封面 | **×1.09** | **−0.06** |
| 播放页色场（平坦） | **×1.28** | **−0.09** |

「亮度 ×1.28」的意思是：面板比它背后的东西亮 28%。那正是「卡片」的定义。

## 二、还有一个死代码问题

`GlassColors.fillTop` / `fillBottom` 从声明起就**没有被任何代码读过**——
主题里写了 `GlassLightTop = Color(0x99FFFFFF)`，组件里却用自己那组写死的值。
所以改主题等于没改。这一批顺手把这两条通路接上，颜色只留一个来源。

（同类问题在前一批的 `edgeHighlight` 上出现过一次，已经修过一次，这次是第二例。）

## 三、改了什么

`ui/theme/Color.kt`

| 常量 | 旧值（从未生效） | 新值 |
|---|---|---|
| `GlassLightBodyTop` | `0x99FFFFFF` | `0x1C28221A` |
| `GlassLightBodyBottom` | `0x4DFFFFFF` | `0x2228221A` |
| `GlassDarkBodyTop` | `0x3DFFFFFF` | `0x404C4238` |
| `GlassDarkBodyBottom` | `0x14FFFFFF` | `0x474C4238` |

新值不是挑色卡挑的，是按「过幕后的亮度」反解的：先定该主题下两个锚点（页面典型底色、
封面滚过时的中间调），要求两处都落在目标亮度上，解出颜色 c 与 alpha a。
浅色要求奶油底 0.93 → 0.84；深色要求深底 0.07 → 0.13（抬起）、亮封面 0.60 → 0.52（压低）。

`ui/glass/GlassSurface.kt`

- `body` 改为读 `glass.fillTop` / `glass.fillBottom`，删掉写死的那组。
- 模糊半径、饱和度、边缘宽度与 alpha **一个都没动**——这一批只改「体」一个变量。

`app/src/test/.../GlassBodyTest.kt`（新增 4 例）

守四件事：薄幕不许接近白色（亮度 < 0.45）、通道极差 ≤ 0.12（不许自带色相）、
alpha 落在 8–16%（浅）/ 20–32%（深）、上下两端必须不同。

## 四、红态验证

把 `GlassLightBodyTop` 改回 `0x99FFFFFF`、`GlassDarkBodyTop` 改回 `0x3DFFFFFF`
（即上一批那组暖白），跑 `GlassBodyTest`：**2 例失败**
（`neitherThemePaintsAWhiteVeil`、`veilAlphaIsStrongEnoughToBeABody`），改回后转绿。
这说明这组断言确实拦得住「又换回白幕」。

## 五、离线复刻

`review/lg-gap-preview.py` 用 PIL + numpy 复刻整条管线（高斯模糊 → 饱和度 → 薄幕 →
SDF 圆角环带亮线/暗带），底图分别取：参考图里的真实壁纸、播放页专辑封面、播放页色场。
每格自动挑「亮度方差最大」的取景窗，避免面板正好压在平坦区上、测到的是取景运气。

输出 `review/2026-10-22-glass-body-preview.png`。换完之后：

| 底图 | 旧（暖白） | 新（暖灰） |
|---|---|---|
| macOS 壁纸 | ×1.06 / Δsat −0.05 | **×0.89 / Δsat −0.10** |
| 播放页封面 | ×1.09 / Δsat −0.06 | **×0.92 / Δsat −0.05** |
| 播放页色场 | ×1.28 / Δsat −0.09 | **×1.15 / Δsat −0.07** |

## 八、还没解决的：底下一片空白

材质这一层现在是「跟着背景走的烟面」，但它跟着什么东西走，取决于背后有什么。
首页那四个玻璃面压在奶油色 / 深棕色的平坦底上，**没有任何结构可以透**，
所以不管材质多准，读起来仍然是一条更深的带子加一圈边。

参考图之所以成立，一半功劳在壁纸。这个 App 里唯一具备同等条件的位置是**播放页的色场**
（`PlayerBackdrop` 随切歌做颜色动画）——但那需要动第 7 版定稿的版式，属于下一批的事。
