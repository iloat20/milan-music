# Release 1.0.74 (vc 75, b75)

本包只有一件事：**会话断开不再崩溃**，以及**音频权限被撤销后界面跟着退回去**。
属于审查里 P1-a 那一批（纯加固，不改任何视觉与交互）。

基线：AGP 9.4.1 / Kotlin 2.4.21 / Gradle 9.8.2 / compileSdk 37 / minSdk 26。

## 1. Service 被系统杀掉后，点播放键会崩

三处条件叠加才会崩，缺一不崩：

1. `PlayerController` 从来没给 `MediaController.Builder` 设 `setListener`。会话断开时
   media3 自己把 controller 置为 released，而字段仍然指向它。
2. 此后任何 `pause()` / `play()` / `seekToNextMediaItem()` / `seekTo()` 都会走
   `checkNotReleased()` 抛 `IllegalStateException`，调用链上没有 try/catch。
3. `AppContainer.scope` 是 `SupervisorJob + Dispatchers.Main.immediate`，**没有**
   `CoroutineExceptionHandler`（`PlaybackService.serviceScope` 一直有），异常直达
   `Thread.uncaughtExceptionHandler`。

触发路径很常见：低内存杀 service、系统后台限制、在设置页"停止"应用后回前台点播放。

改法：

- `sessionListener` 接 `MediaController.Listener.onDisconnected` → `detachSession()`。
- 抽出 `detachSession()`，`release()` 与断连共用一份收尾。`controller == null` 是
  `connect()` 唯一会重新绑定的状态，两条路径必须走到同一个形状上。
- 新增 `sessionCall(action) {}` 包住所有会话调用。`onDisconnected` 是普通主线程消息，
  **落在它被派发之前的那一次点击**仍会看到非空字段并抛出；这一层把那个窗口也吃掉。
  只在 `IllegalStateException` 上生效，且按 error 级带堆栈记账 —— 在错误线程上调用
  同样抛这个类型，必须留在日志里而不是被静默吞掉。
- `release()` 里的 `removeListener` / `release` / `releaseFuture` 各自 `runCatching`：
  原来 `removeListener` 一抛，后面的 `release()` 就永远不执行。
- `seekTo()` 只在会话真的接下这次 seek 之后才发布位置。否则会在已清空的状态上写一个
  "不存在的播放位置"（`detachSession` 刚把它复位成 0）。
- 进度 ticker 与 `subscriptionCount` 收集器也不再从已释放的 controller 读。
  后者尤其重要：它是**唯一**会重新开 ticker 的东西，随着异常一起死掉就再也不会计进度。
- `detachSession()` 清空 `pendingActions`：那些命令是发给已经不存在的会话的，
  回放到新的空会话上等于执行了用户对另一个队列的指令。

**不自动重连**是刻意的：队列在 service 里，新会话必然是空队列。下一次用户动作走
`togglePlayPause` / `play` 的 `pendingActions` 路径重新绑定；清空的 UI 状态是
"现在没有在播"的诚实描述，而不是假装还在播。

## 2. 撤销音频权限后曲库还在，点哪首都没反应

`LifecycleEventEffect(ON_RESUME)` 原来只有单向分支（"授予了但界面还不知道"）。
反方向（在设置里撤销后返回）`hasAudioPermission` 一直是 `true`：列表继续显示内存里的
旧行，而它们指向的 `content://` URI 已经读不到——点下去只有 `PlaybackService` 里的一行
`Log.e`，用户看到的是"点了没反应"，没有报错、没有可重试的入口。

- 判定收进纯函数 `permissionResumeAction(granted, wasGranted)`（`ui/library/PermissionResume.kt`），
  返回 `GRANTED` / `REVOKED` / `UNCHANGED`，`HomeScreen` 只负责执行。
- `REVOKED` 只翻 `hasAudioPermission`，**不清空 ViewModel**：重新授予时
  `refresh()` 会重新扫一遍，保留旧行能让回来的一帧直接有内容，不必先闪一次空列表。
