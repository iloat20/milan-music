# 米兰音乐 1.0.62

本版没有新功能，也不改任何用户可见行为，是一批**结构收敛**：把代码审查报告里 P1 的
三处重复各自收敛成单一入口。改动 11 个文件、新增 4 个，`-304 / +139` 行。

## 一、封面请求只剩一条管线（P1-A）

`ArtworkRepository` 的四个 `load*`（列表 96px / 播放页 512px / 背景板 / 倒影）原本各抄
一份「查 LruCache → 合并同 key 并发请求 → 解码 → 写缓存」，四份里的时序细节一模一样，
且都是**漏了不会报错、只会在真机上表现为"某张封面永远不出来"**的那一类：

1. `peek` 命中必须同步返回，不进挂起、不碰在飞表；
2. 同一 key 只允许一个生产者，快速滚动时一屏十几行请求同一张封面不能解十几份；
3. 生产者中途被取消时，等待方 `await()` 拿到 `null` **必须再 `peek` 一次** —— 生产者
   完全可能在取消之前就已经写好缓存（`loadPlayerArtwork` 的解码就故意跑在
   `NonCancellable` 里）。少了这一步，调用方会把「没拿到」读成「这张专辑没封面」，
   而它的 `LaunchedEffect` key 没变，不会重试。

新增 `data/media/MemoCache.kt`（61 行，`internal`，K/V 泛型，`peek` 由调用方注入，
缓存的所有权仍留在仓库里），`ArtworkRepository` 侧变成四个 `MemoCache` 实例 +
四处 `memo.load(key) { ... }`，四个 `pendingXxx` 表和一个 40 行的私有 `await` 助手删除。

门禁 `MemoCacheTest`（6 例，用 `String` 而非 `Bitmap`，不需要 Robolectric）。三条不变量
逐条做过红态验证：去掉 `?: peek(key)` 只有 `a cancelled producer hands over what it
already cached` 失败；删掉 `pending.remove(key, own)` 只有 `a key that produced nothing
can be retried` 失败。

## 二、动效、收藏按钮、HARDWARE 位图各自收敛（P1-B）

- **`MilanMotion` 增加 `NeighbourSwap` / `PageSwap` / `RiseIn` / `SinkOut`**：原先三处
  `AnimatedContent` 调用点各抄一份 `tween` 链，参数一字不差，只有位移分母不同
  （`/3` 换曲、`/20` 换页）。现在数字不再出现在调用点，`contentSwap` 转 `private`。
- **`ui/components/FavoriteButton.kt`**：列表行与播放页两处收藏按钮的差异只有
  `iconSize`（18 / 24dp）与未选中色（`onBackground.copy(alpha=.5f)` / `OnDark`），
  动画参数（`dampingRatio=0.45f`、`initialScale=0.55f`、`targetScale=0.7f`）完全相同。
- **`Bitmap.softwareCopy(): Bitmap?`**（`data/media/BitmapPixels.kt`）：`HARDWARE` 位图
  的 `getPixels()` 会抛异常，widget 与取色两处原本各写一遍 config 判断。旧写法在
  `copy()` 失败时**返回原图**，调用方必须再检查一次 config，两处的检查时机已经出现过
  偏差；现在统一返回 `null`，语义是「像素读不到」，由调用方决定降级。
