# 第 59 批：滑封面切歌不再闪

日期：2026-10-23 · 版本 1.0.59 (vc 60) → **1.0.60 (vc 61)**
产物：`dist/milan-music-1.0.60-b59-20261023.apk`（2 484 580 B）

## 用户原话

> 滑封面切歌时，会闪一下，很影响观感

## 诊断（不靠猜：三条都在代码里可查）

屏幕下半部分那一大块 = 倒影叠层，它包含**压住封面末段 128dp 的过渡带**（`CoverRamp`）。
它换内容的时候，用户看到的就是"闪一下"。而它的换血时机是错的：

1. **那张翻转位图根本不是它画的东西。** `CoverReflection` 里 `mirror` 只在两处出现：
   第 311 行的 `if (mirror == null) return` 和降级路径的 `Image(bitmap = mirror)`。
   阶梯路径（API 31+）从 `cover` 取行号、在画布上 `translate(0, 2·band)·scale(1,-1)` 翻折 ——
   **`mirror` 一次都没被画**。所以整条带子的"存在与否"，被一张它用不到的位图控制。
2. **那张位图注定晚到。** `reflectionCache = slice(budget, 1, 32)`：24 MB 预算下上限
   786 432 B，而一张 512² 的翻转位图是 1 048 576 B —— `LruCache` 插入时 `size > maxSize`
   就把自己淘汰了。**这个缓存从来没生效过**，每次切歌都重跑一次 512² 翻转（`getPixels`
   + 逐行 arraycopy + `setPixels`），10~30 ms。
3. **它在另一条协程里赋值，和翻页不同帧。** 带子读 `playerState.currentTrack`，轮播要等
   翻页动画走完**并且会话确认**之后才换页（`launchSwitch`）—— 两者天生差几帧。

合起来：切页那一帧只有"页"变了，带子还是旧封面的内容，1~3 帧后才整体换掉。
见 `review/b59-flash-timeline.png`。

## 改法

| # | 改动 | 文件 |
|---|---|---|
| 1 | 新增 `canDrawBand(hasCover, hasMirror, sdkInt)` = `(有封面 && sdk≥31) \|\| 有翻转图`。**三个开关的唯一判据**：带子、封面底边淡出（`heroFadeMask`）、隔壁页底边淡出（`fadeNeighbourBottoms`）—— 三者同生同灭，不会再出现半截状态 | `CoverReflection.kt` |
| 2 | 带子的画源改取**轮播中央那一页**的同步缓存位图（`cachedPlayer`），与那一页画的是同一张 —— 同帧、同像素 | `PlayerScreen.kt` |
| 3 | `CoverCarousel` 新增 `onTrackShown`，所有 `pages` 写入收敛到 `publish` 一个 lambda：`pages = row` 与 `onTrackShown(row.current)` 相邻两行，**同一批快照** | `CoverCarousel.kt` |
| 4 | `playerCache` 2/16 → **3/16**（512² ≈ 1 MB，三页要三张，外加一张余量；原来是恰好卡在边界）；`reflectionCache` 1/32 → **2/32**（先让它至少装得下一张） | `ArtworkRepository.kt` |

第 3 条是"同帧"的全部理由：一个 lambda 里的两条 state 写，会在同一帧的 apply 阶段一起生效；
分成两次写（比如回调里再写一次）必然有一帧错位。

## 顺手查出来、但这批没动

- API 31+ 上 `loadReflection` 产出的位图**仍然没有被任何路径使用**（阶梯路径只吃 `cover`）。
  它现在只在"封面解不出来"时当降级源。若想再省一次翻转，可以按 `SDK_INT < 31` 才加载 ——
  但那会让 API≤30 与 31+ 分叉更多，且这一批要克制，留作单独一项。
- 冷启动（缓存未命中）时 `bandAvailable` 会先 false 后 true，`fadeBottom` 跟着翻一次。
  只在进入播放页的第一帧，且整页本来就在淡入，不处理。
