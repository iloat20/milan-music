# Release 1.0.79 (vc 80, b80)

两处**用户拍板的视觉/交互改动**（前一版列的"剩余三条"里的两条；搜索队列那条按你的决定
保持现状，没动）：

1. **倒影阶梯 5 层 → 3 层**（1080×2400 上约 50MB GPU 缓冲 → 约 30MB）。
2. **进度条命中区 26dp → 48dp**，且**版面一格不动**。

基线：AGP 9.4.1 / Kotlin 2.4.21 / Gradle 9.8.2 / compileSdk 37 / minSdk 26。

## 一 · 倒影阶梯收到 3 层

`BlurRamp` 由 6 个 stop（5 个绘制层）改为 4 个 stop（3 个绘制层）：

| | 半径 | 位置（相对镜面线） |
|---|---|---|
| 保留 | 0dp（由清晰封面本体承担） | -128dp |
| 保留 | 5dp | -44dp |
| 保留 | 12dp | 0dp（镜面线） |
| 保留 | 34dp | +240dp |

去掉的是 `2dp @ -86dp` 与 `22dp @ 96dp`。它们**几乎落在邻两级的连线上**：`blurAt(-86)`
由 2 变 2.5，`blurAt(96)` 由 22 变 20.8，整条曲线偏差 ≤1.2dp；`CoverRamp`（128dp）、
镜面线的 12dp 都原样保留，所以接缝锚点没动。

### 离线对照（`review/ramp3-compare.py`，新写）

原有的 `seam-ramp-preview.py` 是第 45~53 批的模型（`fade` 从镜面线立刻衰减、终点取整幅
倒影高），参数与现在不同，**结论不能互相引用**，所以按 `CoverReflection.kt` 当前的
`layerWeight` / `fadeAt` 逐行重写了一个。用 2026-10-23 那张真机截图当封面源：

```
接缝两侧逐像素差（0 = 完全相同）：
  封面过渡带 (上)      平均 0.13/255   最大 11/255
  接缝 ±8dp           平均 0.00/255   最大  0/255     <- 逐像素完全相同
  镜下 0..64dp        平均 3.09/255   最大 12/255
  镜下 64..128dp      平均 7.87/255   最大 17/255
  镜下 128dp 以下      平均 1.40/255   最大 13/255

接缝亮度台阶 Δ  现状 +0.0000   4 级 +0.0000
接缝硬度        现状 0.40 -> 0.40    4 级 0.40 -> 0.37
```

- **接缝 ±8dp 完全一致**是结构性的：镜面线两侧由同一层、同一次模糊、同一张位图的相邻
  两行画出，层数变了也不影响这一步。
- 唯一变大的是 64..128dp 那段（平均 7.9/255）。那里 `fadeAt` 已衰减到 50% 以下，且
  "糊一点"正好压掉第二张封面的可辨识度；放大 2 倍并排看，两块看不出差别、也没有任何
  带状边界。
- **我自己的脚本第一版是错的**：画布只开到封面高，接缝以下全是越界填充的黑边，于是
  第一次跑出来"镜下全 0 差"—— 一块面板都还没画出来的对比当然完全一致。修掉画布高度
  之后才得到上面的数字。这条留在脚本注释里。

## 二 · 进度条命中区 48dp

`AppleMusicProgress` 里命中区与绘制区拆开：

- 外面是 `Box(height = 48dp)`，手势与 `semantics` 都挂在它上面；
- 里面是原来的 `Canvas(height = 26dp)`，绘制代码一行没改，靠 `contentAlignment =
  BottomCenter` 贴在命中区的**底部**；
- `ProgressTopGap` 由 26dp 收到 **4dp**，把多出来的 22dp 全部还回去。

选择"只向上扩"而不是"上下各借 11dp"是有原因的：后者会让条与时间标签整体下移 11dp，
那是一次可见位移；只向上扩时，条的中心、标签、控制条的绝对位置**一格都没动**
（26 + 26 = 52 = 4 + 48），多出来的只是一段原来空着的可点区域。

顺带修掉同一段里的另一个缺陷：两个 `pointerInput(durationMs)` 以**时长**作 key。时长
一变（首帧 0 → 会话报出真实值、或切歌）就会把**正在进行的拖动取消**掉 —— 手指还在
屏幕上，条却弹回去了。现在改成 `pointerInput(Unit)` + `rememberUpdatedState`，手势里
读的是最新值，key 不再变化。

## 待真机验证

- **倒影接缝**（重点，全设备都要看）：播放页停住，看封面与倒影交界那一行是否有亮线 /
  暗线 / 清晰度跳变。三个位置各看一次：整幅封面可见、封面被横滑移开一半、切歌瞬间。
- **倒影尾部**：镜下 64..128dp 比上一版糊一点是**预期的**；若读成"糊成一团"而不是
  "化进色场"，把最后一档 34dp 收到 28dp 再看（旋钮是半径，不是层数）。
- **进度条命中区**：在条**上方**约 20dp 处横划，也应能拖动；在条上点一下应能跳转。
- **拖动不被切歌打断**：按住进度条拖到一半时让它自然切歌（或让时长首帧才到位），
  手指底下的条不应弹回原位。
- **版面**：时间标签与播放控制的位置应与 1.0.78 完全一致（这次只动了命中区，没动排布）。
