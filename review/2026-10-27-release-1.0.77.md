# Release 1.0.77 (vc 78, b78)

本批是 P2-b，两条独立的"只在特定环境里才对"的缺陷：

1. **"移除动画"在运行期关掉不生效** —— 系统设置改了，界面不会重建，读到的仍是旧倍率。
2. **播放时间标签跟随系统 locale** —— `ar`/`fa`/`bn` 下会用本地数字，进度条两端的标签
   会随着秒数跳动逐秒左右微移。

基线：AGP 9.4.1 / Kotlin 2.4.21 / Gradle 9.8.2 / compileSdk 37 / minSdk 26。

## 一 · 动画倍率只在组合期读一次

`TrackRow.PlayingBars` 原来是：

```kotlin
val context = LocalContext.current
val animationScale = remember(context) { systemAnimationScale(context) }
if (!barsShouldAnimate(animationScale)) { /* 三根静止柱 */ return }
```

判断本身是对的（无限循环动画不会跟随 `ANIMATOR_DURATION_SCALE`，必须显式读），
问题在**读的时机**：`remember` 只在组合期读一次。这个工程里"重新组合"没有保障 ——
`MainActivity` 声明了 `configChanges` 接管方向与主题变化，用户在设置里打开"移除动画"
再切回来，Activity 不重建、`remember` 不重算，于是表现成"下次冷启动才生效"。
而这正是无障碍开关的本意，不是风格微调。

改法：新增 `ui/util/AnimationScale.kt`，`rememberAnimationScale()`：

- `MutableFloatState` 持有当前倍率，`PlayingBars` 在组合期直接读它；
- `DisposableEffect` 里向 `SettingsProvider` 注册 `ContentObserver`
  （`Settings.Global.getUriFor(Settings.Global.ANIMATOR_DURATION_SCALE)`，读全局设置不需要
  任何权限），`onChange` 里重读并写回状态；`onDispose` 注销；
- 重读包了 `runCatching`，失败按 1 处理。**这不只是防御性代码**：`onChange` 跑在主线程，
  那里抛出的异常没有任何人接得住，会直接到 `Thread.uncaughtExceptionHandler`。
- 注销也包了 `runCatching` —— 注销一个没注册成功的观察者会抛，而 `onDispose` 里抛同样无人接。

顺带把旧的一次性读取函数删掉，`TrackRow` 里 `LocalContext` / `Settings` / `remember`
三个导入随之清空（留着就是 `w:`，本工程零警告门禁会红）。

## 二 · `formatDuration` 绑在默认 locale 上

```kotlin
"%d:%02d".format(minutes, seconds)   // → Locale.getDefault(FORMAT)
```

两个后果，第二个才是有害的那个：

1. `ar-EG` / `fa-IR` / `bn-IN` 的默认数字系统是本地数字，输出变成 `٣:٤٥`；
2. 本地数字的字符宽度与拉丁数字不同，而进度条两端的两枚时间标签是**分别居右/居左**
   布局的 —— 秒数每跳一次，两枚标签的宽度就变一次，整条进度条的文字会逐秒微移。
   `ar` 下的冒号位置也会跟着翻。

播放时间是量纲不是文案，改为 `String.format(Locale.ROOT, …)`。
