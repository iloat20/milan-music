# 最佳实践档：把承诺变成门禁（2026-10-29）

接在 b88（1.0.87，ReplayGain 流式读）之后。本批**不改 Kotlin 代码**，只改「怎么证明它是对的」——
所以不产生新版本号，b88 的包仍然有效。

## 一、结论摘要

| 门禁 | 之前 | 现在 |
|---|---|---|
| 成品权限 | README 一段文字 + 人工 `aapt2 dump permissions` | 脚本断言；push 查合并清单，tag 查成品 APK |
| 用例总数 | 无下限 | `>= 290`（当前 295） |
| 取证脚本 | 缺参时用硬编码路径兜底 | 缺参 `exit 2`；非参考宽度显式警告 |

## 二、为什么是这三条，而不是原来列的那三条

上一轮给「最佳实践」列的是：起播延迟、baseline profile 采集、CI 视觉门禁。逐条复核后三项都被否，
换成了上面那三条。理由分别是：

**起播延迟：先测再改。** 上一批的日志已经给出数量级——`queue metadata resolved 5000 items in 12 ms`
（5 000 首）。12 ms 不是「tap 到出声」的主因，而绕开 `setMediaItems` 的 future 要重排队列命令链，
会动到 b87 刚建好的 revision/游标绑定。用一次结构性改动去博一个未经测量的收益，方向不对。

**baseline profile 采集：环境阻塞。** 采集必须连设备（`connectedNonMinifiedReleaseAndroidTest`）。
本机 `adb devices` 为空、`emulator` 命令不存在、BIOS 虚拟化关闭。这一项不是「不做」，是「做不了」，
记在这里而不是假装完成。

**CI 视觉门禁：会在没有设备的地方造出一个假证据。** 倒影的核心是 12/24/34 dp 的阶梯模糊，
Robolectric/SwiftShader 下的模糊与真机 GPU 不是一回事。一个渲染不真实的视觉断言比没有断言更糟——
它会给「几何没问题」的错觉，而本项目所有几何结论本来都建立在真机截图量 std 上。宁可缺，不可假。

换来的三条共同点：**不需要设备、能在 CI 真正执行、失败信息直接指向被违反的那条承诺**。

## 三、权限断言

### 现状与缺口

README 用整段篇幅承诺「只申请本地播放必需的权限」「包里没有任何网络权限」，并列了 6 条。
但在本批之前，这条承诺只靠人工 `aapt2 dump permissions` 核对——谁误删 manifest 里那行
`tools:node="remove"`，`INTERNET` 就静默漏进成品，而 295 个用例和 lint 全都绿。

### 实测暴露的另一件事

成品实际是 **7 条**，README 少了一条：

```
com.milan.music.DYNAMIC_RECEIVER_NOT_EXPORTED_PERMISSION
```

它不在 `AndroidManifest.xml` 里手写，是 AndroidX core 为未导出的动态注册 receiver 自动注入的
包内自定义权限。不授予任何跨应用能力，但**它确实出现在清单里**——文档说 6 条而文件里有 7 条，
是文档与实测不一致。本批两处都修：README 补上并解释来源，脚本里也列进去。

列它的另一个原因是让断言是「精确相等」而不是「包含」：如果只检查「白名单里的都在」，
将来任何新增的传递权限都不会被发现。

### 脚本

`review/check-shipped-permissions.py`，两种输入等价：

```
aapt2 dump permissions app-release.apk | python review/check-shipped-permissions.py --stdin
python review/check-shipped-permissions.py --manifest AndroidManifest.xml
```

退出码：`0` 一致 / `1` 多一个、少一个或 `maxSdkVersion` 不符 / `2` 输入无法解析。

`--stdin` 是显式的，不靠「没给参数就去读 stdin」来猜：那样在交互终端里误跑一次就会挂在等待
输入上，没有任何提示（第一版就是这么写的，本地跑一次就发现了）。

### 红态验证

| 构造 | 退出码 | 报错 |
|---|---|---|
| 注入 `INTERNET` | 1 | 禁止的权限出现在成品里 + 指出它来自 Media3 传递引入 |
| 追加 `CAMERA` | 1 | 白名单外的新权限 + 提示「加权限是一次产品决定」 |
| 空输入 | 2 | 没有解析到任何 uses-permission |
| 清单路径不存在 | 2 | 读不出清单 |

绿态：成品 APK、以及 `merged_manifest` / `merged_manifests` / `packaged_manifests` 三份清单
逐一断言，都是 7 条一致。

## 四、用例数下限

让门禁变绿最容易的方式是删掉失败的那个测试。CI 现在断言 `tests >= 290`（当前 295），
注释里写清楚「只升不降，真要删就得同时改这里的数字，那道摩擦是有意的」。

与 `--rerun-tasks` 配套：不重跑的话 `test-results` 是上一轮的旧结果，这条断言会统计到旧数据。

## 五、取证脚本的两个静默失败

改之前，`review/` 下两个几何取证脚本都有「忘了给路径」的兜底：

- `seam-audit-shot.py` 默认指向 `C:\Users\...\clipboard-images\clipboard-2026-10-23T....jpg`
  —— 那是一张**真实存在过的截图**。于是「忘了给路径」和「给了路径」跑出来的是同一串数值，
  没有任何提示说明验错了图。
- `mirror-audit.py` 默认 `"shot.jpg"`，在别人目录里要么报一句 file not found，
  要么恰好命中一张无关的图并打印一整屏 NCC。

两处都改成缺参 `exit 2` 并打印用法。**参数校验放在 `from PIL import Image` 之前**——
否则缺依赖的环境会先抛 `ModuleNotFoundError`，把「忘了给路径」伪装成「环境没装好」。

顺带修了同一类问题的第三个：`seam-audit-shot.py` 的几何常量（64 dp 带宽、422 dp 镜面线）
全部按 390 dp 宽标定，但对任何尺寸的图都会照算，输出一屏带小数点的错数值。现在：

- 宽度换算出的 dp 宽超出 380~400 时，向 stderr 打印显式警告，说明数字不能直接套用；
- 新增 `--density <px per dp>`，非参考机可以指定真实密度后继续用。
