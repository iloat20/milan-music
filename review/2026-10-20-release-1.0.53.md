## 1. 换曲即播（`PlayerController`）

### 1.1 症状与根因

暂停状态下点「下一首」，队列指针确实移到了下一曲，但不出声，表现像"点了没反应"。

根因是 media3 的语义：`seekToNextMediaItem()` / `seekToPreviousMediaItem()` 只移动播放位置，**不改 `playWhenReady`**。暂停时该标志为 false，换曲后依然 false，于是指针到位、播放器仍停着。

1.0.52 及更早的 `next()` 只有这两行：

```kotlin
if (mediaController.hasNextMediaItem()) {
    mediaController.seekToNextMediaItem()
} else if (mediaController.mediaItemCount > 0) {
    mediaController.seekTo(0, 0L)
}
```

### 1.2 处理

新增 `resumeIfPaused(MediaController)`，只在**真正换曲**的分支调用：

```kotlin
private fun resumeIfPaused(mediaController: MediaController) {
    if (mediaController.playWhenReady) return
    if (mediaController.playbackState == Player.STATE_IDLE) {
        mediaController.prepare()
    }
    mediaController.play()
}
```

三处调用点与边界：

| 方法 | 调用位置 | 说明 |
|---|---|---|
| `next()` | 全部（含队列到头回到第一首） | 循环播放语义，任何一次都是换曲 |
| `previous()` | 仅 `hasPreviousMediaItem()` 分支 | 3 秒窗口内的「回到本曲开头」不调用——那不是换曲意图 |
| `skipToPrevious()` | 无条件 | 封面左滑手势，与按钮语义不同：滑动手势本身即表达"要上一首" |

两个实现细节：

- **判据用 `playWhenReady` 而非 `isPlaying`**。缓冲期间 `isPlaying` 也会是 false，用它判断会在每次缓冲时重复下发 `play()`。
- **`STATE_IDLE` 先 `prepare()`**。暂停后若播放器已回到 IDLE，直接 `play()` 不会启动，必须先 prepare 建立渲染管线。

### 1.3 一处注释与实现不一致（未修改）

`resumeIfPaused` 的 KDoc 写「队列到头的 `seekTo(0)` 都不动播放状态」，但 `skipToPrevious()` 是在 if/else **之外**无条件调用的，因此 `else` 分支（队列第一首、`seekTo(0L)`）同样会 resume。

按手势语义判断这是可接受的行为（用户主动左滑即代表播放意图），所以本版**保留实现、不动代码**，仅在此记录差异。若要严格对齐注释，把该行移进 `if (mediaController.hasPreviousMediaItem())` 分支即可。

## 2. 米兰 tab 点击旋转（`HomeScreen`）

`GlassBottomBar` 里新增累积角度状态：

```kotlin
var spinTarget by remember { mutableFloatStateOf(0f) }
val spin by animateFloatAsState(
    targetValue = spinTarget,
    animationSpec = tween(MilanMotion.SlowMs, easing = MilanMotion.Standard),
    label = "tab-taiji-spin",
)
```

| 项 | 取值 |
|---|---|
| 单次角度 | +180° |
| 时长 / 曲线 | `MilanMotion.SlowMs` = **420 ms**，`FastOutSlowInEasing` |
| 触发条件 | `index == 0`（米兰）；长按重新扫描的逻辑不变 |
| 应用位置 | 图标 `graphicsLayer { rotationZ = if (index == 0) spin else 0f }`，文字不转 |

存**累积角度**而不是布尔开关：连点时角度叠加（180 → 360 → 540），动画始终朝同一方向接续，不会在中途"掉头"回到原位。太极是黑白双色对称图形，180° 后两半互换位置，观感是"翻面"而不是"转回去了"。

喜欢 tab 的心形不加旋转——它是非对称图形，转 180° 会颠倒。

## 4. 已知边界

- **无真机验证**。旋转的动画观感（420 ms 是否偏慢）、暂停状态下点下一首的实际出声时机，均未在设备上确认。
- **`skipToPrevious()` 的注释与实现不一致**，见 §1.3，本版未修。
- 换曲即播依赖 `MediaController` 的异步语义：`prepare()` 与 `play()` 是串行下发的两个命令，播放器在 IDLE 状态下收到 `play()` 时会自行处理准备流程，但 `prepare()` 到实际出声之间仍有一次缓冲往返，本版未量化该延迟。
