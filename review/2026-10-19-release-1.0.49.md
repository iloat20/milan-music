本版是 **1.0.48 的缺陷修复版**。1.0.48 发布后的代码审查（`review/2026-10-19-code-review-1.0.48.md`）判定 3 条阻断、6 条高优先；本版闭合全部 3 条阻断 + 3 条高优先，并把 release 收敛为 64 位单 ABI。

## 为什么是 1.0.49 而不是重发 1.0.48

`v1.0.48` 的 tag 已指向 `b90a9c7`，Release 资产已上传（APK 2,477,875 B / AAB 5,916,840 B，均为 4 ABI）。`versionCode 49` 已经用掉——内容变更必须提升 `versionCode`，否则后续任何上传渠道（含 Play）都会因重复版本号被拒。因此本版为 `versionCode 50`、新 tag `v1.0.49`。

## 64 位打包收敛

`app/build.gradle.kts` 的 `release` 块新增 `ndk { abiFilters += "arm64-v8a" }`（`debug` 不受影响，仍含 4 ABI 以便 x86 模拟器调试）。

审计（`review/2026-10-19-abi-audit.md`）结论：

- release 运行时依赖 **105 个**，其中仅 **2 个**含原生库，均提供 arm64-v8a：`androidx.graphics:graphics-path:1.0.1`、`androidx.datastore:datastore-core-android:1.2.1`；
- 其余 103 个产物无 `jni/` 目录，且所有依赖内**没有**落在 `jni/` 之外的 `.so`（这条必须单独查：`abiFilters` 只过滤 `jni/` 派生的 `lib/<abi>/`）；
- 成品 APK 内 2 个 ELF 均为 `64-bit AArch64`，无任何 32 位 ELF；AAB 内为 `base/lib/arm64-v8a/` 唯一。

| 指标 | 1.0.48（4 ABI） | 1.0.49（arm64） |
|---|---|---|
| APK 字节数 | 2,477,875 | 2,379,987 |
| `lib/` 条目数 | 8 | 2 |
| `classes.dex` | 3,808,120 | 3,809,428 |

> 体积巧合说明：1.0.48 的 arm64 试打包产物与本版 APK 字节数完全相同（2,379,987 B），但内容不同——SHA-256 分别为 `2461008a…` 与 `80d725db…`。原因是 `versionName` 同为 8 个字符，R8 输出长度未变。

## 与 1.0.48 的用户可感知差异

1. **release 不再支持 32 位设备**（armeabi-v7a 已移除），纯 32 位机型无法安装。
2. 重打标签后**当次冷启动即生效**，不再需要手动刷新或等待重启。
3. 小组件遇到无法绘制的封面时**降级为占位图**，不再有崩溃路径。
4. 解码器初始化失败时**会回退到下一个候选**，而不是直接播放失败。

## 尚未验证（需真机）

按优先级：

1. **B2**：`loadThumbnail` 返回 HARDWARE 位图的设备上，`adb logcat -s MusicWidget` 应无 `cover render failed`，且小组件正常显示封面。
2. **B3**：`adb logcat -s PlaybackService | grep "audio decoder="` 应仍为 `c2.android.inproc.*`（顺序未变），失败路径需人为制造才能验证。
3. **P1-2**：播完一张专辑后按 Home，`TRIM_MEMORY_BACKGROUND` 下缓冲池应真正释放（`dumpsys meminfo` 对比）。
